This SysML v2 model describes a `MiningFrigate`, a spaceship designed for mining asteroids.  The frigate is defined within a package named `MiningFrigate`, which imports several other packages containing definitions for scalar values,  data structures (ISQ), SI units, metadata about parameters of interest, operational use case actions, and a general `Domain` package.

**Mining Frigate Attributes and Parts:**

The `MiningFrigate` itself has several attributes:

* `miningRate`:  The volume of ore mined per second (m³/s).
* `droneCapacity`: The maximum number of drones the frigate can deploy.
* `threatDetectionRange`: The range at which the frigate can detect threats (in astronomical units - AU).
* `fleetSize`: The maximum size of a mining fleet the frigate can coordinate.

The frigate is composed of several parts, some configurable and some not:

* **Non-Configurable:** `coreSystem` (a core system with no further detail in this model).
* **Configurable Modules:**
    * `miningLaser` (1 or 2):  A mining laser with attributes for `miningPower` and `cycleTime`.
    * `shieldModule`: A shield generator with `shieldStrength` and `rechargeRate`.
    * `propulsionModule`: A propulsion system with `maxVelocity` and `warpSpeed`.
    * `sensorModule`: A sensor array with `scanResolution` and `targetingRange`.
    * `oreHoldExpander` (0 to 2): Optional modules to increase cargo capacity (`capacityBonus`).
    * `capacitorBooster` (0 or 1): Optional module to boost capacitor recharge (`capacitorRecharge`).
    * `defenseTurret` (0 to many): Optional defense modules with `firepower` and `optimalRange`.
* **Other Parts:**
    * `cargo` (0 to many):  References to `Domain::CargoContainer` objects.
    * `charge`: A reference to a `Domain::Power` object representing the frigate's power source.
    * `drone` (0 to 5): References to `Domain::Drone` objects.


**Ports:**

The `MiningFrigate` has several ports for interaction:

* `controlPort`:  Connects to a `Domain::PodPort` for pilot control.
* `dockingPort`: Connects to a `Domain::DockingPort` for docking with stations.
* `DefensePort`: Connects to a `Domain::ThreatPort` for handling threats.
* `asteroidOrePort`: Connects to a `Domain::AsteroidOrePort` for ore extraction.
* `droneControlPort`: Connects to a `Domain::DroneControllerPort` for drone management.

**Actions:**

The model defines one action explicitly:

* `activateMiningLaser`: An action to activate the mining laser.

**States and Transitions:**

A state machine, `miningFrigatesStates`, defines the possible states of the frigate:  `Packaged`, `Parked`, `Docked`, `InGrid`, and `OnWarp`.  Transitions between these states are triggered by specific events (e.g., receiving a `pilotPodUndockCommand`) and actions (e.g., `undockFromStation`).  Many internal transitions within the `InGrid` state handle actions like mining, scanning for threats, deploying drones, and navigation.  The model also includes transitions for cargo unloading, resupply, and threat engagement.

**Other Definitions:**

The model includes definitions for `SpaceshipModule` (a base class for modules), `CoreSystem` (the non-configurable core), and detailed definitions for each of the configurable modules.  These provide attributes relevant to each module's functionality.

In summary, the model provides a comprehensive description of a mining frigate, including its components, capabilities, and operational states.  The use of parts, ports, and actions allows for a modular and reusable representation.  The state machine captures the dynamic behavior of the frigate during its operation.
