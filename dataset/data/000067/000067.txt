This model describes a system for managing and classifying information or components based on their security sensitivity. It's not a physical object, but rather a blueprint for the security architecture of a system that handles sensitive data, such as one used in a government, military, or corporate intelligence context.

The system establishes a formal security framework with three distinct classification levels: Unclassified, Confidential, and Secret. Various assets within the system—which could represent documents, data files, software modules, or even physical components—are tagged with these security labels.

For example, the system contains several components (`x`, `y`, `z`) that are all subject to security controls. Two of these components are classified as "Confidential," indicating they contain sensitive information that requires protection. A third, more critical component (`z`) is designated as "Secret," signifying a higher level of sensitivity and requiring stricter handling and access controls. This framework ensures that different parts of the system are clearly marked according to their security requirements, forming the basis for implementing access control and data handling policies.
