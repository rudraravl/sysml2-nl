This model describes a modular and configurable vehicle system built from a set of six distinct components. The overall design is based on combining different versions of two main subsystems, "Subsystem A" and "Subsystem B," to create a final vehicle configuration.

The vehicle's architecture is highly flexible. **Subsystem A** can be assembled in one of two ways: either using Component 1 and Component 2, or by using Component 2 and Component 3. This means Component 2 is a common part of Subsystem A, while Components 1 and 3 are mutually exclusive options.

Similarly, **Subsystem B** has two variants. It can be built with Component 4 and Component 5, or with Component 5 and Component 6. In this case, Component 5 is the core, always-present part of Subsystem B, while Components 4 and 6 are the optional alternatives.

A key element of this system is **Component 5**, which is not only a structural part but also has a configurable behavior. It can be set to perform one of two different functions, referred to as "Action X" or "Action Y."

The components are designed to work together in specific ways. For instance, if the vehicle is built with the version of Subsystem A that includes Component 3, a specific connection is established between Component 3 and the configurable Component 5 in Subsystem B.

However, not all combinations are allowed. There is a critical design rule that **forbids** combining the "Component 2 and 3" version of Subsystem A with the "Component 5 and 6" version of Subsystem B. This specific pairing is considered an invalid configuration.

The model presents two examples of specific vehicle builds:

1.  **Vehicle Configuration A:** This is a valid design. It uses the "Component 1 and 2" version of Subsystem A and the "Component 4 and 5" version of Subsystem B. In this configuration, the versatile Component 5 is specifically set to perform "Action X."

2.  **Vehicle Configuration B:** This configuration is defined but is actually **invalid** because it violates the system's core design rule. It attempts to pair the "Component 2 and 3" version of Subsystem A with the "Component 5 and 6" version of Subsystem B. In this illegal build, Component 5 would have been set to perform "Action Y."
