This model represents a complete system designed to analyze the cybersecurity of a modern, network-connected medical infusion pump. The system includes the pump itself, the patient it's treating, the clinical workstation used to control it, and a malicious attacker attempting to compromise it.

The central component is the **Infusion Pump**, a medical device used to deliver controlled amounts of medication or fluids to a patient. It's a sophisticated piece of equipment with several key internal parts. A **therapy engine** is responsible for actually administering the medication according to prescribed parameters like dosage rate and duration. For safety and security, the pump is equipped with a dedicated **security module** that validates incoming commands, handles encryption, and checks authentication credentials to ensure only authorized personnel can control the device. It also features an **anomaly detector** that monitors network traffic for unusual patterns that might indicate a cyberattack, and an **audit logger** that records all commands and system events for later review.

The pump operates in different states. It starts in `Standby`, waiting for a command. When a command arrives, it enters an `Authenticating` state. If the command is legitimate, the pump proceeds to `Delivering` therapy. However, if an unauthorized command is detected, it enters an `Alarming` state and can escalate to a full `Lockdown` to prevent patient harm.

This pump exists within a larger clinical environment. It is connected to a **Healthcare Network**, which has its own security features like firewalls. A doctor or nurse uses a **Clinical Workstation** to legitimately program the pump, sending secure and authenticated commands over this network. The pump is physically connected to a **Patient**, monitoring their vital signs and delivering the prescribed therapy.

The system is primarily designed to simulate a "hijack scenario" where a malicious **Attacker** attempts to take control of the pump. The attacker uses their own tools, represented as an exploit framework and a command injector, to find vulnerabilities in the pump and send malicious commands. The model outlines the entire attack sequence, from the attacker identifying the pump on the network to attempting to alter the therapy parameters. The goal is to demonstrate how a successful attack could cause the pump to deliver a dangerous, incorrect dosage, leading to patient harm, and to test how the pump's built-in security features can detect and block such an attack.
