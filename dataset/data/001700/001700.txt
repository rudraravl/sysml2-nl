This model describes a comprehensive Email Client application, similar to desktop or mobile apps like Microsoft Outlook or Apple Mail. It's designed to let a user compose, send, receive, and manage their electronic messages.

The system is built from several specialized components that work together. A **User Interface** provides the primary means for a user to interact with the application, allowing them to write new emails and view their inbox. When composing a message, a dedicated **Message Composer** takes the user's input—such as recipients, subject, and body text—and structures it into a formal email message, assigning it a unique ID.

For outgoing mail, the system uses a **Message Queue** that can hold up to 10,000 pending messages. This acts as a buffer, ensuring that emails aren't lost if the network connection is slow or temporarily unavailable. An **SMTP Client** component is responsible for pulling messages from this queue and sending them over the internet using the standard SMTP protocol. The sending process is robust, moving through distinct states like connecting to a server, authenticating, transmitting the data, and finally confirming whether the delivery was successful or failed.

For incoming mail, a **Spam Filter** first analyzes each message. It checks the sender and content to calculate a spam score. If the score is above a set threshold, the message is automatically quarantined. Legitimate emails are passed on to be stored and displayed to the user. All emails, whether incoming, outgoing, or quarantined, are managed by a **Message Store**, which acts as the local database for the inbox, sent items, and spam folders, operating within a defined storage capacity.

At its core, the system operates on a detailed representation of an **Email Message**, which includes standard fields like sender, recipients, subject, body, timestamp, and size, as well as its current status (e.g., draft, sent, read, failed) and priority level.
