This model describes a configurable vehicle product line built on a modular architecture. The core design allows for the creation of different vehicle models by selecting from a predefined set of options for its major subsystems.

The vehicle is composed of two main customizable modules, "Subsystem A" and "Subsystem B". Each of these modules has two different versions, or variants, that can be installed:

*   **Subsystem A** can be built as either `subsystem1` (composed of Part 1 and Part 2) or `subsystem2` (composed of Part 2 and Part 3). This indicates that Part 2 is a common component used in both versions of this subsystem.
*   **Subsystem B** can be configured as either `subsystem3` (using Part 4 and Part 5) or `subsystem4` (using Part 5 and Part 6). Similarly, Part 5 is a shared component between both options for Subsystem B.

A critical engineering rule governs how these subsystems can be combined: if the `subsystem2` variant is chosen for Subsystem A, then the vehicle *must* be equipped with the `subsystem3` variant for Subsystem B. This suggests a technical dependency or compatibility requirement between these specific parts.

The model presents two distinct, pre-approved vehicle configurations that follow this rule:

1.  **Vehicle Configuration A**: This model is built using `subsystem1` for Subsystem A and `subsystem3` for Subsystem B.
2.  **Vehicle Configuration B**: This model uses `subsystem2` for Subsystem A, and as required by the design rule, is paired with `subsystem3` for Subsystem B.
