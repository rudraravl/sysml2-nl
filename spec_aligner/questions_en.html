sysml2-nl Alignment Question Bankv0.1.6

Annotated reference for spec_aligner/QUESTIONS.md and spec_aligner/questions.json — every universal question, every template, the answering protocol, the scoring rules, and the seven-wave calibration record.

In one paragraph: this bank is the measurement instrument that replaced the deprecated regex aligner. The paradigm is twin-blind QA (compare QAGS/QAEval for summarization, TIFA/DSG for text-to-image): one LLM answers every question reading only the natural-language description, a second answers the same questions reading only the SysML v2 code, and the agreement between the two answer sets is the alignment signal. Questions that disagree localize the mismatch to a single fact and carry two-sided evidence, which becomes the direct input for repair feedback.

1. Architecture: two tiers plus distractors

Tier 1 — universal (45 questions, fixed)

Category-level existence and counting questions, answerable for any sample whatsoever. This tier is the cross-sample-comparable "public ruler": because every sample gets the same 45 questions, scores are directly comparable across samples and across generators.

Category weights follow measured construct frequency over the 1935 gold models: port 96%, attribute 92%, part def 89%, action 88%, requirement 83%, connect 81%, constraint 74%, state 64%. Constructs that appear more often get more questions and therefore more weight.

Tier 2 — templates (27 templates + 3 distractor templates, instantiated per sample)

A question-writer LLM reads both modalities and fills the slots, targeting 30–60 instances per sample. This tier reaches fact granularity: named entities, containment, connections, concrete values, bounds, state transitions.

Distractors

Fabricated-fact questions whose true answer is no/not_stated on both sides. They never enter the similarity score; they exist to estimate each answerer's hallucination rate and act as a reliability gate.

Per sample: 45 universal + 30–60 instantiated + distractors ≈ 80–110 questions, each answered twice.

2. The five non-negotiable question rules

  1. Closed answer space. Every question is multiple choice, and not_stated is automatically appended to every one of them.
  2. Atomic. One fact per question — otherwise a disagreement cannot be localized to anything actionable.
  3. Neutral vocabulary. Questions are phrased in plain domain language. Facts that exist only in SysML are described functionally (part def PressureRegulator → "a pressure regulator"), never by identifier. Pasting the identifier would leak the answer to the SysML side.
  4. Options harvested from both modalities for value questions, so that a 12V-vs-10V conflict surfaces as two different committed options rather than both sides retreating to "other".
  5. depends_on skip logic applies at scoring time only. Answerers answer everything; dependencies are used later to exclude children.

3. Answering protocol: asymmetric worldviews

The most important design decision in the whole instrument: the two answerers reason under deliberately different rules. An NL description is inherently partial; SysML code is inherently complete. Treating them symmetrically would charge the model for every fact the prose simply didn't mention.

AnswererWorldviewWhat silence means
NL Open world The text is a partial description. Fact not mentioned → not_stated; never infer "no" from silence. Answer no/none only on explicit denial or clear exclusivity ("communicates only via X"). Do not import plausible engineering facts the text does not state.
SysML Closed world The code is the complete model. Construct absent from the code → no/none, not not_stated. Reserve not_stated for genuinely inapplicable or unreadable questions. The prompt carries a SysML v2 notation cheat-sheet (from mycelium-hypha knowledge/textual-notation/index.md) so :>>, alias, and connect…to… are read correctly.

NL-side tightening rules v0.1.1+

Calibration showed the NL answerer over-committing in specific, recurring ways. Each of these clauses was added to kill a class of false mismatch:

  • Generic mentions don't establish existence. "its attributes", "various parameters", "several settings" → not_stated, not "yes".
  • Non-exhaustive lists are not counts. "including X, Y", "such as X" must not be read as an exact count. If the text states no complete count, answer not_stated on count questions.
  • Purposes and goals are not requirements. Only explicit obligations (shall / must / required / stated rules) count. Goal-flavored prose yields not_stated on requirement questions — never "no".
  • Closed-world options must be explicitly claimed. declared_without_value, no_bound, no_threshold, not_assigned are positive claims the text must actually make; silence about a value or bound means not_stated, never one of these.
  • System-wide "how many" needs a complete enumeration. A partial mention → not_stated. A stated count for one named element ("over 170 stations", "two units") may be committed.
  • Adjectives of purpose are not is-a relations. "specialized", "dedicated" describe what a thing is for; they do not state subtyping.

SysML-side encoding-equivalence rules v0.1.1+

The mirror problem: the same engineering fact has several legal encodings in SysML v2, and the answerer was penalizing the model for choosing a different-but-valid one. The worldview now says to read encodings semantically:

  1. Package-as-system. Parts declared directly inside a package are the system's top-level components; treat the package as the overall system component containing them.
  2. Multiplicity states counts. [0..2] = optional up to two, [2..*] = at least two, [1] = exactly one. Answer count, threshold and optionality questions from these bounds.
  3. Rules have many encodings. Requirement constructs, constraint blocks, multiplicity bounds, doc shall-statements, or optimization objectives (e.g. MaximizeObjective) — all count as the model stating an obligation.
  4. Transfer has many encodings. Flow statements, typed directional ports (in/out payloads) plus connections, action parameter chaining (in x = other.y), or successions — all count as flow/connectivity between the owning components.
  5. A requirement's subject ≠ its satisfier. The subject is what the requirement constrains; satisfaction is expressed via satisfy/allocation.
  6. Branching ≠ event-wait. Decide nodes, if actions, or guarded transitions are branching. An accept/when trigger alone (wait-then-continue) is not.

Shared rules

  • Answer from the provided document only; the other modality is never shown.
  • Bridge vocabulary yourself: questions use plain language, you map to identifiers ("the battery" ≈ part battery : BatteryPack).
  • Every committed answer must carry an evidence span; lazy uniform answers are detectable and rejected.
  • Answer all questions independently; temperature 0; strict JSON, one record per question.
  • "other" has a precise meaning v0.1.2: the document states a specific value different from every listed option. If the document states no value at all, the answer is not_stated.
  • Options name referents, not wordings. Choose the option denoting the same thing even when the document words it differently.
  • Numeric equivalence v0.1.2: approximate and exact statements of one quantity are the same option ("over 2 m" matches "2010 mm"; a stated "0.03 mm" matches a bound option "<= 0.03 mm"). Use "other" only for a genuinely different value.
  • Consistency rule v0.1.5: if the document's statement is consistent with a listed option — implies it or is implied by it ("about 10 s" vs "<= 10 s", "multiple" vs "1 or more", "capacity of 250 kg" vs ">= 250 kg") — and nothing else matches better, choose that option. Never escape to "other" or not_stated over wording differences.

Execution

  • LLM calls go through codex exec v0.1.6 — single-shot, read-only sandbox, ChatGPT sign-in (the nl2sysml/ablation_gpt55/batch_codex_gpt55.py scheme, no API billing).
  • Sharded answering: per modality the question list is split into 5 contiguous shards answered by 5 parallel codex processes, merged before scoring.
  • NL answers are cached per (sample, bank version, question-set hash) and reused across every candidate SysML (gold / codex / gpt55 / RAG …) — this halves the cost of each additional generator you evaluate.

4. Scoring

not_stated – extra_in_model — 0.85–1.0

  • Vacuous agreement is excluded. Both sides saying "nothing here" is not evidence of alignment, so padding questions cannot inflate similarity.
  • extra_in_model is judged by the question's origin tag. A sysml-origin fact the NL never mentioned is legitimate elaboration (credit 1.0), not a defect; other origins get 0.85.
  • Adjacent-bucket partial credit v0.1.5: for ordinal option sets (count_bucket), a conflict between neighbouring buckets scores 0.7 instead of 0.0 and is demoted to low severity — boundary fuzz is not a real clash.
  • Similarity S = mean credit over scored questions (non-vacuous, non-distractor, dependency-satisfied), reported overall plus a per-category vector across structure / interface / connectivity / attribute / constraint / requirement / state / action / classification. That vector is the radar-chart payload.
  • Dependency handling. Enforced at scoring, not answering: a child is excluded unless its parent is aligned and the parent's NL answer equals the required value. This prevents double-penalty cascades where one wrong root answer sinks five children.
  • NL answer remap v0.1.3: declared_without_value from the NL side is deterministically rewritten to not_stated — prose that omits a number is not the same as prose asserting there is no number.
  • Distractor handling. Distractors never enter S. Per answerer, reliability = share of distractors answered no/not_stated; reliability < 0.5 flags the whole answer set for re-answering or review.
  • Canary handling. U-GLB-01 disagreement is a standalone red flag (likely wrong pairing or degenerate generation), independent of S. Two refinements: answers in generic_or_abstract / other are wildcards that don't trigger it, and v0.1.4 the flag now also requires a global collapse (S < 0.7) — adjacent-domain fuzz on an otherwise well-aligned pair is not a red flag.
  • Low-signal marker. A run with fewer than 30 scored questions is flagged low_signal — the score exists but is thin.
  • Mismatch report. Every non-aligned scored question becomes a record: {qid, category, origin, tier, text, outcome, severity, credit, nl answer+evidence, sysml answer+evidence, metamodel_refs, anchors}, sorted high→low severity. Severity: conflict = high, missing_in_model = medium, unverifiable/extra = low.

5. Tier 1: all 45 universal questions

Option sets: yes_no; count_bucket = none / one / two / three_to_five / more_than_five (ordinal); count_coarse = none / one / multiple v0.1.1; domain = nine values. not_stated is implicitly appended everywhere. The "Dependency" column means the question is only scored when that parent is aligned on that answer.

Three questions were deleted during calibration and are noted in place below: U-CST-02 and U-REQ-02 (counting constraints/requirements has M:N semantics — one prose obligation legitimately becomes three constraint blocks, so the count question measured encoding style, not alignment) and U-CLS-03 (alias, ~4% of the dataset — almost always vacuous).

6. Tier 2: all 27 templates

A template is not a question — it is an instruction for writing questions. ⟨…⟩ marks a slot the question-writer LLM fills after reading both modalities. Key fields:

  • options — fixed choices. options_rule — choices must be harvested from both modalities and deduplicated. That harvesting is the mechanism that turns a value conflict into a clean disagreement.
  • origin — whether the fact came from NL only, SysML only, or both; scoring uses it to interpret asymmetric outcomes.
  • instantiate_when — the precondition for emitting the question at all.
  • max_instances — hard per-sample cap; excess is discarded, so the writer must spend the quota on its most salient findings.

8. Instantiation rules

  • Target: 30–60 instantiated questions per sample. The writer's input is both the NL text and the SysML code.
  • Priorities:
    1. Every numeric value/bound in either modality gets a T-ATT-02 / T-CST-01 / T-REQ-03 question.
    2. Every connection and flow in either modality gets a T-CON-* question.
    3. Salient entities, states, actions next, up to each template's cap.
    4. Distractors last (2–5 per sample).
  • Vocabulary bridging. Question text must be understandable from the NL alone. SysML-only facts are described functionally from name, doc comment and type (part def PressureRegulator → "a pressure regulator"); never paste raw identifiers like p1 or camelCase names.
  • Origin tagging. Each question records nl / sysml / both. v0.1.2 Tag both only when the NL states the fact explicitly enough that a strict literal reader would commit; when in doubt, tag sysml or nl. This gating matters because origin=sysml converts an extra_in_model outcome from 0.85 to full credit.
  • Option harvesting — one option per referent v0.1.1–0.1.5. This grew into the longest rule in the bank because it was the single largest noise source: the writer kept emitting two options for one thing, forcing a spurious conflict.
    • Same thing, different words ("dried scrubs" vs "dry scrubs", "numerical score" vs "real number") → one option labeled with both phrasings ("dried scrubs / dry scrubs"). Only genuinely different values get separate options.
    • Labels stay short and canonical (~4 words max); never embed sentences.
    • Approximate vs exact but consistent ("over 2 m" vs "2010 mm") → merge into one option: "2010 mm (over 2 m)".
    • Several things flowing between one pair → bundle into one option ("position + weight"). But if the two modalities name different payload sets for one link, don't force a single choice — emit one yes/no question per payload.
    • Different granularities of one referent are one option: "processed gesture data (type + position + orientation)".
    • Scale-equivalent unit spellings are the same fact: merge "5.5 um" and "5.5e-6 m". Counts too: "at least 2" and "2" → "2 (at least 2)". Triggers too: a narrated trigger and its signal name → "vehicle-on signal (running confirmed)".
    • Never probe the same fact with two templates (e.g. T-CST-01 and T-REQ-03 on one bound) — pick the better fit.
  • Slot quality v0.1.3: attribute slots must be quantifiable properties (mass, speed, capacity), never adjectives ("interchangeable" is not an attribute). Component counts belong in T-STR-03, not T-ATT-02. Action slots must be genuine behaviors, never structural relations (connecting, containing, being typed by). Entity slots use the bare entity ("battery"), never unverifiable qualifiers ("rechargeable battery") — a qualifier belongs in its own attribute question.
  • Quota. Never exceed max_instances; excess is discarded and wastes budget on your most salient findings.
  • Distractor verification. A fabricated slot value must not appear in either modality, literally or as a synonym; the generator self-checks and replaces violations.
  • Anchors. Per question the writer records where the fact came from (nl_span, sysml_lines) for mismatch reporting — and anchors are stripped before questions reach the answerers, since an anchor would leak the answer.
  • ID format: Q-<sample_id>-<template_id>-<n>, e.g. Q-000050-T-CON-01-1.

10. Validation, worked example, pipeline

Validation plan

  1. Golden set — the 10 samples drawn with seed 20260708 (the same seed as the legacy regex test, including 000050); instantiated questions and expected answers hand-reviewed and kept as regression fixtures.
  2. Perturbation sensitivity — mutate one fact in an aligned sample's SysML (change a bound value, delete a connect, rename a state); the corresponding question's outcome must flip to conflict/missing. Automated. This is the test that the ruler has gradations at all.
  3. Question health — track per-question vacuous rate (>80% → demote), NL not_stated rate, and distractor failure rate; prune or rephrase on each version bump. (U-CLS-03 was flagged here and duly deleted in 0.1.1.)
