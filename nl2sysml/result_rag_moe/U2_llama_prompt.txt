Example 1 NL:
This model describes a specialized quadcopter drone designed for forest fire observation and surveillance.

The drone is built with a standard quad-rotor airframe, consisting of a central body, four arms, and landing gear. It is propelled by four engines, with two propellers rotating clockwise and two counter-clockwise to provide lift and stable, maneuverable flight.

Engineered for extended missions, the drone is equipped with a high-capacity, long-distance battery. A central power management module is responsible for monitoring the battery's charge status and distributing electricity to the four engines and other electronic components.

The drone's "brain" is a flight control unit that manages all aspects of its operation. It relies on a suite of sensors for navigation and stability: a GPS module for determining its location, an Inertial Measurement Unit (IMU) for sensing orientation and movement, and a barometer for precise altitude control. Crucially, the flight control unit constantly receives battery status updates from the power management module, allowing it to manage flight time and execute return-to-base procedures when power is low.

For its primary observation role, the drone is fitted with a camera. It also includes an obstacle avoidance sensor to enhance safety during flight. A complete communication system, with a radio transmitter, receiver, and antenna, enables it to be controlled remotely and transmit data, such as a live video feed, back to an operator.

Example 1 SysML:

Example 2 NL:
This model represents a generic battery-powered electronic device and an analysis of how it can fail. The device consists of a main unit and a battery, which has a measurable power level.

The model describes a specific failure scenario that begins with a root cause: the battery becoming old. The analysis shows that an aging battery can lead to a situation where its power level drops below the minimum threshold required for the device to function. This low-power condition then directly causes the device to shut down completely. This shutdown is classified as a high-severity failure, indicating that the device's continued operation is critical and its unexpected failure has significant consequences.

Example 2 SysML:
package 'User Keyword Example' {
	private import ScalarValues::Real;
	private import 'Semantic Metadata Example'::*;
	private import RiskMetadata::LevelEnum;
	part def Device {
		part battery {
			attribute power : Real;
		}
	}
	#scenario def DeviceFailure {
		ref device : Device;
		attribute minPower : Real;
		#cause 'battery old' {
			:>> probability = 0.01;			
		}
		#causation connect 'battery old' to 'power low';
		#situation 'power low' {
			constraint { device.battery.power < minPower }			
		}
		#causation connect 'power low' to 'device shutoff';
		#failure 'device shutoff' {
			:>> severity = LevelEnum::high;
		}
	}
}

Example 3 NL:
This model describes a battery-powered medical device and the potential consequences of its failure on a patient.

The system consists of the medical device itself, which relies on an internal battery for power, and its interaction with a patient receiving treatment. The device's primary function is to provide some form of therapy.

The model highlights a critical failure pathway. The device's operation is dependent on its battery, which can fail in two ways: it can either be depleted of its charge, or it can degrade to a point where it can no longer be recharged. Either of these battery issues will directly cause the entire medical device to stop working. Consequently, when the device fails, it leads to a delay in the patient's prescribed therapy.

Example 3 SysML:
package MedicalDeviceFailure {
	private import CauseAndEffect::*;
	part medicalDevice {
		part battery {
			event occurrence depleted;
			event occurrence cannotBeCharged;
		}
		event occurrence deviceFails;
		ref patient {
			event occurrence therapyDelayed;
		}
		#multicausation connection {
			end #cause ::> battery.depleted;
			end #cause ::> battery.cannotBeCharged;
			end #effect ::> deviceFails;
		}
		#causation connect deviceFails to patient.therapyDelayed;
	}	
}

Example 4 NL:
This model represents the fuel delivery system for a vehicle, specifically focusing on an integrated fuel tank assembly. This assembly contains the two primary components: a fuel tank for storing the fuel and a fuel pump for delivering it.

In operation, the fuel pump draws fuel from the tank and supplies it to the vehicle's engine. The system is also designed with a fuel return circuit, which allows any unused fuel from the engine to flow back directly into the tank for storage. This design represents a common configuration in modern vehicles where the pump is located inside the fuel tank.

Example 4 SysML:

	part def FuelTank;

			}

				out item fuelOut : Fuel;
				in item fuelIn : Fuel = fuelTankPort.fuelReturn;

Example 5 NL:
This model describes a long-range drone designed to operate up to 5 kilometers away from its user.

The drone's ability to achieve this long-distance flight is based on a specific balance between its weight and power source. It incorporates a high-capacity battery, specified to hold at least a 6000 mAh charge, which provides the necessary energy for extended flight. To maximize the effectiveness of this power source, the drone's overall design is very lightweight, with a total mass strictly controlled to not exceed 750 grams.

This combination of a powerful battery and a lightweight frame is the core technical approach used to satisfy the primary requirement for long-range operation.

Example 5 SysML:
package Drone_BaseArchitecture {
    part def Drone;

        doc /* The drone shall have a sufficient range 
             * to operate at a distance of 5 km from the 
             * operator's location.
            */  
        subject drone : Drone_BaseArchitecture::Drone;
    }
}
package Drone_SystemArchitecture {
    part drone : Drone_BaseArchitecture::Drone {
        attribute totalMass = 750;
        part battery {
            attribute capacity = 6000;
        }        
    }
    satisfy Drone_StakeholderRequirements::longDistance by drone;  
}
package Drone_SystemRequirements {
    import RequirementDerivation::*;
    requirement <'REQ-9942'> totalMass {
        subject drone :>> Drone_SystemArchitecture::drone;        
        assert constraint {
            drone.totalMass <= 750
        }
    }
    requirement <'REQ-9943'> battery {
        subject battery :>> Drone_SystemArchitecture::drone.battery;
    }
    requirement <'REQ-9944'> maxCapacity {
        subject battery :>> Drone_SystemArchitecture::drone.battery;
        assert constraint {
            battery.capacity >= 6000
        }
    }
    #derivation connection {
        end #original ::> Drone_StakeholderRequirements::longDistance;
        end #derive ::> Drone_SystemRequirements::totalMass;
        end #derive ::> Drone_SystemRequirements::maxCapacity;
    }
}
