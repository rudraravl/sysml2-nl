Example 1 NL:
This model describes a mechanical powertrain system, where the central component is an engine designed to generate rotational force (torque).

The system is defined by its core function: to act as a torque generator. A fundamental requirement is that it must produce a positive amount of torque, meaning it's capable of actively creating rotational power.

In the physical design, this function is carried out by a powertrain assembly. Within this powertrain, the engine is the specific component that performs the action of generating torque. Essentially, the abstract, functional role of a "Torque Generator" is physically realized by the engine component of the overall powertrain system.

Example 1 SysML:
package '12b-Allocation-1' {
	private import SI::*;
	private import RequirementModel::*;
	private import LogicalModel::*;
	private import PhysicalModel::*;
	package RequirementModel {
		requirement torqueGeneration {
			subject generator: TorqueGenerator;
			require constraint { 
				 generator.generateTorque.torque > 0.0 [N*m]
			}
		}
	}
	package LogicalModel {
		action def GenerateTorque { out torque :> ISQ::torque; }
		part def LogicalElement;
		part def TorqueGenerator :> LogicalElement {
			perform action generateTorque : GenerateTorque;
		}	
		action providePower {
			action generateTorque : GenerateTorque;
		}
		part torqueGenerator : TorqueGenerator {
			perform providePower.generateTorque :>> generateTorque;
		}
		satisfy torqueGeneration by torqueGenerator;			
	}
	package PhysicalModel {
		part def PhysicalElement;
		part def PowerTrain :> PhysicalElement;
		part powerTrain : PowerTrain {
			part engine {
				perform providePower.generateTorque;
			}
		}
	}
	allocation def LogicalToPhysical {
		end logical : LogicalElement;
		end physical : PhysicalElement;
	}
	allocation torqueGenAlloc : LogicalToPhysical 
		allocate logical ::> torqueGenerator to physical ::> powerTrain {
		allocate torqueGenerator.generateTorque to powerTrain.engine.generateTorque;		
	}
}

Example 3 NL:
This model represents a digital camera designed to capture photographs of an external scene. The camera is composed of two primary internal subsystems that work in sequence: an autofocus subsystem and an imaging subsystem.

When a picture is taken, the autofocus subsystem first observes the real-world scene the camera is pointed at. Its function is to process this view and produce a sharp, focused optical image. This focused image is then passed directly to the imaging subsystem. The imager, which represents the camera's digital sensor, captures this incoming focused light and converts it into a final digital picture. This newly created photograph is then stored within the camera.

Example 3 SysML:
package Camera {
	private import 'Action Decomposition'::*;
	part def Camera;
	part def FocusingSubsystem;
	part def ImagingSubsystem;
	part camera : Camera {
		ref item scene : Scene;
		part photos : Picture[*];
		part autoFocus {
			in ref item scene : Scene = camera::scene;		
			out ref item realImage : Image;
		}
		flow autoFocus.realImage to imager.focusedImage;
		part imager {
			in item focusedImage : Image;		
			out item photo : Picture :> photos;
		}
	}
}

• step implies subsetting timeEnclosedOccurrences. These are features of behaviors typed by

instead of from and to, respectively.

behavior Manufacture {
step paint : Paint [1];
step dry : Dry [*];
succession p_before_d first [1] paint then [1] dry;
step ship : Ship [*];
succession d_before_s first [1] dry then [1] ship;
