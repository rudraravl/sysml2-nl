Example 1 NL:
This model describes an intelligent battery charging system, composed of a power system and the battery it manages.

The system's primary function is to automatically charge a battery to its full capacity. It operates using a continuous feedback loop. The process begins by monitoring the battery to determine its current charge level. Based on that level, the system makes a decision: if the charge is less than 100%, it continues to supply power to the battery.

This cycle of monitoring the charge and then applying more power repeats until the battery reaches a full 100% charge. At that point, the system automatically ends the charging process to prevent overcharging.

Example 1 SysML:
package 'Decision Example' {
	private import ScalarValues::*;
	attribute def BatteryCharged;
	part battery;
	part powerSystem;
	action def MonitorBattery { out charge : Real; }
	action def AddCharge { in charge : Real; }
	action def EndCharging;
	action def ChargeBattery {
		first start;
		then merge continueCharging;
		then action monitor : MonitorBattery {
			out batteryCharge : Real;
		}
		then decide;
			if monitor.batteryCharge < 100 then addCharge;
			if monitor.batteryCharge >= 100 then endCharging;
		action addCharge : AddCharge {
			in charge = monitor.batteryCharge;
		}
		then continueCharging;
		action endCharging : EndCharging;
		then done;
	}
}

Example 3 NL:
This model describes an intelligent battery charging system. The system is composed of a battery and a power system designed to manage the charging process.

The system's primary function is to safely and automatically recharge the battery to its full capacity. The charging process operates as a continuous feedback loop. First, the power system monitors the battery's current state of charge. As long as the charge level is below 100%, the system actively supplies power to the battery. This cycle of monitoring the charge and then adding more power repeats continuously.

Once the system detects that the battery has reached a full charge, it automatically terminates the charging process. This prevents overcharging, ensuring the safety and longevity of the battery.

Example 3 SysML:
package 'Control Structures Example' {
	private import ScalarValues::*;
	attribute def BatteryCharged;
	part battery;
	part powerSystem;
	action def MonitorBattery { out charge : Real; }
	action def AddCharge { in charge : Real; }
	action def EndCharging;
	action def ChargeBattery {
		loop action charging {
			action monitor : MonitorBattery {
				out charge;
			}
			then if monitor.charge < 100 {
				action addCharge : AddCharge {
					in charge = monitor.charge;
				}
			}				
		} until charging.monitor.charge >= 100;
		then action endCharging : EndCharging;
		then done;
	}
}

A supply line moves fuel from the tank assembly to the engine, and a return line carries any unused fuel back from the engine to the tank. A key feature of this system is that the temperature is monitored at the fuel connection points on both the engine and the tank assembly, indicating that fuel temperature is a critical operational parameter.

7.2.2.1 Elements and Relationships Overview

Elements are the constituents of a model. Some elements represent relationships between other elements, known as
the related elements of the relationship. In general terms, a model is constructed as a graph structure in which
relationships form the edges connecting non-relationship elements constituting the nodes. However, since
relationships are themselves elements, it is also possible in KerML for a relationship to be a related element in a
relationship and for there to be relationships between relationships.
