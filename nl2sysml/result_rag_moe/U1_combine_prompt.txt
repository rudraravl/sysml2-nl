Example 1 NL:
This model represents the core powertrain and vehicle dynamics of an electric vehicle (EV), designed for simulating and analyzing performance characteristics like range, efficiency, and speed. It defines a modular system that can be configured to represent different classes of vehicles.

The system is centered around a vehicle body, which has physical properties like mass and is subject to forces such as air friction. The vehicle's motion is described by its acceleration, velocity, and the distance it has traveled.

Its powertrain consists of three main components that work together to produce motion:

1.  **Battery:** This is the energy source for the EV. It's characterized by its voltage, total energy capacity (in ampere-hours), and internal resistance. In operation, it supplies electrical current to the motor, and its state of charge (SoC) decreases as it's used.

2.  **Electric Motor:** This component converts electrical energy from the battery into mechanical power. It takes in voltage and, in response, draws a current to produce a rotational force (torque). Its performance is influenced by its internal resistance and inductance.

3.  **Tire:** This represents the wheel and drivetrain assembly. It takes the rotational torque from the motor and converts it into a linear force that pushes against the road, propelling the vehicle forward. The tire's radius and moment of inertia are key factors in this conversion.

In operation, the battery supplies voltage to the motor, which generates torque to spin the tires. The tires apply force to the road, accelerating the vehicle. The vehicle's motion creates feedback, such as load on the tires, which in turn affects the torque required from the motor and the current drawn from the battery.

The model is used to evaluate different EV configurations against specific performance requirements. Two distinct variants are defined: a lighter "compact" vehicle and a heavier "large" vehicle. Each configuration is then tested against its own set of targets, such as achieving a minimum driving range (e.g., 130 km for the compact), a certain energy efficiency, and a required maximum speed. This allows for the analysis and verification of different vehicle designs before they are built.

Multiplicity is defined in the Core layer as a feature for specifying cardinalities (number of instances) of a type by
enumerating all numbers the cardinality might be (see 7.3.2.2 ). The Kernel layer provides a specific way to do this
by specifying a range of cardinalities. A multiplicity range has lower bound and upper bound expressions that are
evaluated to determine the lowest and highest cardinalities, with both expression evaluating to natural numbers (that
is, of type Natural from the ScalarValues library model, see 9.3.2 ). An upper bound value of * (infinity) means
that the cardinality includes all numbers greater than or equal to the lower bound value.
A multiplicity range is written in the form [lowerBound..upperBound], where each of lowerBound and
upperBound is either a literal expression or a feature reference expression represented in the notation described in
7.4.9 . Literal expressions can be used to specify a multiplicity range with fixed lower and/or upper bounds. If the
result of the lowerBound expression is *, then the meaning of the multiplicity range is not defined.
A multiplicity range can also be written without the lower bound (or ..). In this case, the result of the single
expression is used as both the lower and upper bound of the range, unless the result is the infinite value *, in which
case the lower bound is taken to be 0.
Multiplicity ranges can be used in the declaration of types, particularly features (see 7.3.4.2 ).

		attribute nominalVoltage : ISQ::electricPotential;
		attribute maxSpeed : ISQ::angularVelocity { value in NonSI_Units::RevolutionsPerMinute; }

		// Internal physical properties for simulation.
		attribute internalResistance : ISQ::resistance;
		attribute torqueConstant : ISQ::torque / ISQ::electricCurrent;
		attribute backEmfConstant : ISQ::electricPotential / ISQ::angularVelocity;

		// Physical interfaces for power exchange.
		port electricalInput : ElectricalConnector;
		port mechanicalOutput : MechanicalShaft;

		// Constraints defining the electro-mechanical behavior based on physics.
		constraint VoltageBalance {
			doc /* The input voltage equals the sum of the voltage drop across the
			    /* internal resistance and the back-EMF generated by rotation.
			    /* V_in = I * R + Ke * omega */
			electricalInput.power.voltage =
				(electricalInput.power.current * internalResistance) +
				(backEmfConstant * mechanicalOutput.power.angularVelocity);
		}

		constraint TorqueGeneration {
			doc /* The output torque is directly proportional to the current
			    /* drawn by the motor, governed by the torque constant.
			    /* T_out = Kt * I */
			mechanicalOutput.power.torque =
				torqueConstant * electricalInput.power.current;
		}

		constraint PowerConservation {
			doc /* Electrical power in must equal mechanical power out plus power lost as heat. */
			let elecPower = electricalInput.power.voltage * electricalInput.power.current;
			let mechPower = mechanicalOutput.power.torque * mechanicalOutput.power.angularVelocity;
