Example 1 NL:
This model represents the process of a digital camera taking a photograph. The system operates as a sequence of distinct actions that transform a real-world view into a final, viewable image.

The process is initiated by a user trigger, such as pressing the shutter button, which identifies the desired real-world **scene** to be captured. The first automated step is to **focus**, where the camera's lens system adjusts to create a sharp, clear optical **image** of that scene on its internal sensor.

Immediately following the focus, the camera performs the **shoot** action. This is the moment of capture, where the light and color data from the focused image is read by the sensor and processed into a digital **picture** file.

Finally, this newly created picture is sent to be **displayed**, allowing the user to instantly review the photo they have just taken, typically on an LCD screen on the back of the camera. Once displayed, the camera is ready to capture the next scene.

Example 1 SysML:
package 'Merge Example' {
	part def Scene;
	part def Image;
	part def Picture;
	action def Focus { in item scene : Scene; out item image : Image; }
	action def Shoot { in item image : Image; out item picture : Picture; }
	action def Display { in item picture : Picture; }
	action def TakePicture;
	action takePicture : TakePicture {
		first start;
		then merge continue;
		then action trigger {
			out item scene : Scene;
		}
		flow from trigger.scene to focus.scene;
		then action focus : Focus {
			in item scene;
			out item image;
		}
		flow from focus.image to shoot.image;
		then action shoot : Shoot {
			in item image ;
			out item picture;
		}
		flow from shoot.picture to display.picture;
		then action display : Display {
			in item picture;
		}
		then continue;	
	}
}

This describes a system structured with a classic three-tier software architecture, likely for a purpose like calculating a price or a result based on specific inputs.

The system is organized into three distinct, dependent layers:

1.  An **Application Layer**, which serves as the user-facing part of the system where data is entered.
2.  A **Service Layer**, which contains the core business logic and performs the main calculations or operations.
3.  A **Data Layer**, which is responsible for storing and retrieving the information the Service Layer needs to function.

In operation, the Application Layer relies on the Service Layer to process user requests. The Service Layer, in turn, depends on the Data Layer to access necessary information (like pricing tables, user data, or configuration settings).

The system's core function is to calculate a final value (represented by `z`) that is directly determined by two other independent input values (represented by `x` and `y`). For instance, a final shipping cost (`z`) would be calculated based on the package's weight (`x`) and the shipping distance (`y`).

Example 3 NL:
This model describes a generic system designed for interaction with a user. The two primary components are the 'System' itself and an external 'User'.

The main purpose of this arrangement is for the user to operate the system to achieve a specific, defined goal. This core user-system interaction is broken down into two essential sub-functions or steps, referred to as UC1 and UC2. For the user to successfully use the system and achieve their goal, they must engage in both of these sub-functions as part of the overall process.

The system is designed with the inherent capabilities to perform these functions. The model also outlines a more comprehensive, higher-level scenario (UC3) that encompasses the entire standard user-system interaction. This suggests that the basic operation of the system can be a component or a step within a larger, more complex workflow.

Example 4 NL:
This describes the automated process of a digital camera system for taking a photograph. The system is designed to capture a real-world scene, process it, and display the final result.

The process begins when a user aims the camera at a "scene." The system's first step is to "focus," which adjusts the optics to create a sharp, clear "image" on the camera's sensor. Immediately following this, the "shoot" action captures this focused image, converting it into a final digital "picture." As the final step, this newly created picture is sent to be displayed on a "screen," providing immediate visual feedback to the user.

Example 4 SysML:
package 'Messaging Example' {
	item def Scene;
	item def Image;
	item def Picture;
	attribute def Show {
		item picture : Picture;
	}
	action def Focus { in item scene : Scene; out item image : Image; }
	action def Shoot { in item image : Image; out item picture : Picture; }
	action def TakePicture;
	action screen;
	action takePicture : TakePicture {
		action trigger accept scene : Scene;
		then action focus : Focus {
			in item scene = trigger.scene;
			out item image;
		}
		flow from focus.image to shoot.image;
		then action shoot : Shoot {
			in item image; 
			out item picture;
		}
		then send new Show(shoot.picture) to screen;
	}
}

Example 5 NL:
This model describes the interaction within a vehicle's cruise control system, which is designed to automatically maintain a steady speed set by the driver.

The system involves the driver and several key components within the vehicle: the cruise control unit (the system's brain), the speedometer, and the engine.

The process is initiated when the driver sets a desired cruising speed. This command is sent to the vehicle's cruise control unit. The system then enters a control loop where the speedometer continuously senses the vehicle's actual speed and sends this data to the cruise control unit. The cruise controller compares the driver's target speed with the real-time sensed speed and, based on the difference, sends a command to the engine to adjust the fuel intake, thereby speeding up or slowing down the vehicle to maintain the constant, desired speed.

Example 5 SysML:
package 'Interaction Example-1' {
	public import 'Event Occurrence Example'::*;
	item def SetSpeed;
	item def SensedSpeed;
	item def FuelCommand;
	occurrence def CruiseControlInteraction {		
		ref part :>> driver;		
		ref part :>> vehicle;
		message setSpeedMessage of SetSpeed 
			from driver.setSpeedSent to vehicle.cruiseController.setSpeedReceived;
		message sensedSpeedMessage of SensedSpeed 
			from vehicle.speedometer.sensedSpeedSent to vehicle.cruiseController.sensedSpeedReceived;
		message fuelCommandMessage of FuelCommand 
			from vehicle.cruiseController.fuelCommandSent to vehicle.engine.fuelCommandReceived;
		first setSpeedMessage then sensedSpeedMessage;
	}
}
