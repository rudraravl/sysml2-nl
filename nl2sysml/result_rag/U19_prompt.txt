Example 1 NL:
This model describes a basic fuel system for a machine, likely a vehicle or a generator. The system consists of two primary components: an Engine and a Fuel Tank.

The Fuel Tank serves as the reservoir, providing a supply of fuel. The Engine consumes this fuel to generate power. A key feature of this system is the two-way connection between the components. Fuel flows from the tank to the engine, but there is also a dedicated return line allowing unused fuel to flow back from the engine to the tank.

This entire interaction is managed through a specialized, compatible port on each component. Example 2 NL:
This model describes the complete lifecycle of a vehicle, from its creation to its disposal.

The vehicle's life begins with an assembly phase where it is manufactured. Following its construction, there is a specific delivery event, which is recorded with a formal delivery date.

After delivery, the vehicle enters its operational life, which can consist of sequential periods of ownership by different people. Each period of ownership starts with a sale event. Throughout a period of ownership by a specific person, the vehicle can be driven on multiple occasions. The system tracks who is driving the vehicle during each of these periods, recognizing that the driver may be different from the legal owner.

Finally, the vehicle's lifecycle concludes with a final event when it is junked or scrapped, marking its end of service.

package 'Time Slice and Snapshot Example' {

	item def Person;

		first assembly then delivery;
		snapshot delivery {
			attribute deliveryDate : Date;
		}
		then timeslice ownership[0..*] ordered {
			snapshot sale = start;
			ref item owner : Person[1];
			timeslice driven[0..*] {
				ref item driver : Person[1];
			}
		}
		snapshot junked = done;
	}
}

This model represents a fundamental mechanical power system, such as the core of a vehicle's propulsion system or an industrial generator.

The system is built around a physical **PowerTrain**. The primary function of this system is to provide power, which it achieves by generating torque (rotational force). Within the PowerTrain, there is an **engine** that is the specific component responsible for creating this force.

Essentially, the system defines the abstract concept of a "Torque Generator" and assigns this functional role directly to the physical PowerTrain, clarifying that the powertrain is the hardware that fulfills the job of creating rotational force.

Example 5 NL:
This model describes the fundamental process of a camera taking a photograph. The system's purpose is to transform a real-world scene into a final, captured picture.

This is achieved through a distinct, two-step sequence:

1.  **Focus:** The process begins when the camera targets a `Scene`. It performs a "focus" action, which adjusts the camera's optics to create a sharp, clear `Image` on its internal sensor. This image is a temporary, intermediate representation of the scene.

2.  **Shoot:** Once the sharp image is formed on the sensor, the camera immediately performs a "shoot" action. This step captures the focused image, converting it into the final, permanent `Picture`.

The system mandates that these actions must occur in this specific order. Focusing must be completed before the shot can be taken, as the result of the focus action (the sharp image) is the necessary input for the shoot action.

Example 5 SysML:
package 'Action Succession Example-1' {
	item def Scene;
	item def Image;
	item def Picture;
	action def Focus { in scene : Scene; out image : Image; }
	action def Shoot { in image: Image; out picture : Picture; }	
	action def TakePicture {
		in item scene : Scene;
		out item picture : Picture;
		bind focus.scene = scene;
		action focus: Focus { in scene; out image; }
		flow from focus.image to shoot.image;
		first focus then shoot;
		action shoot: Shoot { in image; out picture; }
		bind shoot.picture = picture;
	}
}
