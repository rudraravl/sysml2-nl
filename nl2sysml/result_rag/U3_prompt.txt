Example 1 NL:
This describes a sensor management function within a larger system. This function is responsible for systematically updating a group of sensors.

Each sensor in the group has a status that indicates whether it is "ready" to be updated. A sensor might be considered ready if it is powered on, has completed its self-test, and is not currently busy with another task.

The update process works by checking each sensor in the collection one by one. If a sensor is marked as "ready," the system proceeds to perform an update on it. This update could involve recalibrating the sensor, polling it for new data, or refreshing its internal state. Any sensor that is not in a "ready" state is simply skipped by this process.

Example 1 SysML:
package 'Opaque Action Example' {
	part def Sensor {
		attribute ready : ScalarValues::Boolean;
	}
	action def UpdateSensors {
		in sensors : Sensor[*];
		language "Alf" 
			/* 
			 * for (sensor in sensors) {
			 *     if (sensor.ready) {
			 *         Update(sensor);
			 *     }
			 * }
			 */
	}
}

Example 2 NL:
This model describes a vehicle and trailer towing system. The system consists of three main components: a vehicle, a trailer, and a separate trailer hitch assembly that connects them.

The trailer hitch assembly is the central connecting element and is composed of two key parts: a hitch ball and a trailer coupler.

In this configuration, the vehicle itself does not own the hitch ball, but is set up to interface with the one provided by the hitch assembly. Similarly, the trailer connects to the trailer coupler, which is also part of that same hitch assembly.

Essentially, the system shows a vehicle and a trailer being joined together by a common, self-contained hitch mechanism.

Example 3 NL:
This model describes an automotive cruise control system designed to automatically maintain a vehicle's speed as set by the driver. The system is composed of several key components working in concert: a central Cruise Controller, a Speedometer, the vehicle's Engine, and the Driver who operates it.

The process is initiated by the Driver, who sends a command to set a desired speed. This command is received by the Cruise Controller, which acts as the brain of the system. To regulate the speed, the controller needs to know how fast the vehicle is currently moving, so it receives a continuous stream of data from the Speedometer.

By comparing the driver's desired speed with the actual speed reported by the speedometer, the Cruise Controller calculates whether to accelerate or decelerate. It then sends a precise fuel command to the Engine, which responds by adjusting its power output to match and maintain the target speed without further input from the driver.

Example 3 SysML:
package 'Event Occurrence Example' {	
	part def Driver;
	part def CruiseController;
	part def Speedometer;
	part def Engine;
	part def Vehicle;
	part driver : Driver {
		event occurrence setSpeedSent;
	}
	part vehicle : Vehicle {
		part cruiseController : CruiseController {
			event occurrence setSpeedReceived;		
			then event occurrence sensedSpeedReceived;		
			then event occurrence fuelCommandSent;
		}
		part speedometer : Speedometer {
			event occurrence sensedSpeedSent;
		}
		part engine : Engine {
			event occurrence fuelCommandReceived;
		}
	}
}

Example 4 NL:
This is a model of a conventional, configurable automobile designed for transporting a driver and passengers. It features a traditional rear-wheel-drive powertrain, starting with a fuel tank that supplies an internal combustion engine, which can be configured with either four or six cylinders.

The engine's power is transferred through a transmission (with options for automatic or manual variants), down a driveshaft, to a differential in the rear axle assembly. The differential then distributes torque to the two rear wheels. The vehicle's chassis includes distinct front and rear axle assemblies, wheels, and a body assembly that incorporates safety features like bumpers, seat belts, and airbags, as well as security systems like an alarm and keyless entry.

A central software-based vehicle controller manages the car's operations. This includes a cruise control system that uses a speed sensor to maintain a set velocity. The vehicle operates in several states: it is `off` when parked, transitions to a `starting` state when the driver presses the brake and turns the ignition, and enters an `on` state for driving. While running, it continuously monitors its health, for example, by sensing its temperature, and can enter a `degraded` state if it overheats or a `maintenance` state when service is due. The model also defines the vehicle's mission, which involves a driver and passengers getting into the car, driving to a destination, and exiting.

The conditional test operator if is followed by three operands, with the symbol
? after the first operand and the keyword else after the second operand. A conditional expression
evaluates to the value of its second or third operand, depending on whether the result of its first operand is
true or false. Note that only one of the second or third operand is actually evaluated.
if x >= 0? x else -x

• Binary operator expressions. A binary operator is one that has two operands. The binary operators include
numerical operators (+, -, *, /, %, ^, **), logical operators (&, |, xor), comparison operators (==, !=, <, >,
<=, >=, ===, !==), and the range construction operator (..). In general, both operands become arguments
of the invocation expression, with their results being passed to the invocation of the function represented
by the operator. However, the null-coalescing (??), conditional and (and), conditional or (or) and
implication (implies) operators all correspond to control functions in which their second operand is only
evaluated depending on a certain condition of the value of their first operand (whether it is null, true, false,
or true, respectively).
x + y

The operators == and != apply to operands that have single values, testing whether they are equal or
unequal, respectively. They also evaluate to true or false, respectively, if their operands are both null (no
values). The operators === and !== apply specifically to values that are occurrences (see 9.2.4 ). They test
whether two occurrences are portions (in space and/or time) of the same life occurrence. Informally, these

occurrences), === and !== are the same as == and !=.
