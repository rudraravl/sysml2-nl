This contract provides a generic execution engine for performing multiple on-chain operations in a single transaction, acting as a batch executor. It doesn't maintain any persistent state beyond its own code. Callers can use the `execute` function to submit a series of calls to other contracts, optionally including native currency transfers. The contract supports different execution modes: a single batch of calls, a single batch with additional operational data (`opData`), or a batch of batches, where each inner batch is processed recursively. Access control for single batches without `opData` is restricted to the contract itself, meaning only the contract can initiate these internal calls. For batches with `opData`, the contract expects an override to implement custom authorization logic based on the provided `opData`. There are no explicit events emitted by this contract. A notable mechanic is the use of assembly for efficient decoding of call data and execution, and it will revert if any of the batched calls fail.
