This contract serves as a foundational component for interacting with a PoolManager, enabling the movement and settlement of various currencies. It maintains no direct state itself, instead relying on an external PoolManager to track currency deltas (debts and credits). Callers can initiate two primary operations: `_take`, which withdraws a specified amount of a given currency from the PoolManager and sends it to a recipient, and `_settle`, which pays a specified amount of currency to the PoolManager. The `_settle` function handles both native currency and ERC-20 tokens, synchronizing with the PoolManager before payment. Access control for these operations is not directly implemented in this contract but is expected to be managed by inheriting contracts. The contract defines abstract functions for specific payment mechanisms (`_pay`) and provides utility functions to calculate amounts based on contract balance or open deltas with the PoolManager, ensuring amounts are positive for credits and negative for debts. It emits errors if unexpected delta signs are encountered or if there's an insufficient balance for wrapping/unwrapping operations.
