This contract serves as an upgradeable proxy for another contract, enabling its underlying logic to be modified over time without changing the proxy's address. It maintains two key pieces of state: the address of the current implementation contract and the address of the administrative account. Upon deployment, it is initialized with an initial implementation address and an admin address. Callers interact with this proxy as if it were the implementation contract itself; all calls are forwarded to the current implementation. However, if the designated admin account calls the proxy, it can perform administrative operations such as retrieving the current implementation or admin addresses, changing the admin to a new address, or upgrading the implementation to a new contract address, optionally executing an initialization function on the new implementation. An `Upgraded` event is emitted when the implementation changes, and an `AdminChanged` event is emitted when the admin address is updated, allowing off-chain systems to track these critical lifecycle events. The contract implements a transparent proxy pattern, ensuring that only the admin can access administrative functions, preventing potential function selector clashes with the underlying implementation.
