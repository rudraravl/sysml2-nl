This contract acts as a transparent upgradeable proxy, allowing an underlying implementation contract to be swapped out while maintaining the same contract address and state. It stores an immutable admin address, which is an instance of a `ProxyAdmin` contract created during deployment, and the address of the current implementation logic. Callers interact with the proxy, which forwards calls to the current implementation unless the caller is the designated admin. If the admin calls the proxy, they can only execute the `upgradeToAndCall` function to change the implementation contract and optionally initialize it; any other call by the admin will revert. Non-admin callers always have their calls forwarded to the current implementation. The `ProxyAdmin` contract, which owns the upgradeability rights, can transfer its ownership to another address, thereby controlling who can initiate upgrades. This design prevents function selector clashes between the proxy and the implementation, ensuring predictable behavior and secure upgrades.
