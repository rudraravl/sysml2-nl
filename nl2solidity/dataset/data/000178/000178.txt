This contract implements a binary heap data structure, specifically designed to manage a collection of `uint256` values as a priority queue. It maintains its state as an ordered array of these `uint256` values, representing the heap's tree structure. Callers can perform several operations: `peek` to retrieve the highest priority element without removing it, `pop` to remove and return the highest priority element, `insert` to add a new element, `replace` to atomically remove the highest priority element and insert a new one, `length` to query the number of elements, and `clear` to empty the heap. Access control is not explicitly defined, as this is a library intended for use by other contracts, meaning any contract that uses it can call its functions. There are no events emitted, fees, or direct upgradeability mechanisms. A notable mechanic is the ability to use custom comparator functions, allowing the heap to function as either a min-heap (default) or a max-heap, but mixing comparators during the heap's lifecycle will lead to undefined behavior. The contract guards against panics for operations on an empty heap.
