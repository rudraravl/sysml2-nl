This contract serves as an upgradeable proxy, enabling the logic of a dApp to be updated without changing the contract's address. It maintains a single piece of state: the address of the current implementation contract, stored in a specific storage slot to prevent conflicts. Upon deployment, it is initialized with an initial implementation address and can optionally execute an initialization function on that implementation. All calls made to this proxy contract are automatically delegated to the current implementation contract, meaning the proxy itself does not contain any business logic. A public function `implementation()` allows any caller to query the address of the currently active logic contract. The contract emits an `Upgraded` event whenever the implementation address is changed, allowing off-chain systems to track upgrades. The contract ensures that any new implementation address provided during an upgrade points to a valid contract.
