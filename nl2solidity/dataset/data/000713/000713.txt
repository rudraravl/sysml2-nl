This contract serves as a configuration manager for defining parameters related to invariant testing, specifically for fuzzing. It maintains various lists of addresses, artifact names, and selector-address pairs, categorizing them as either "excluded" or "targeted." Callers can add new entries to these internal lists to specify which contracts, senders, artifacts, or specific function selectors should be included or excluded during testing. The contract provides separate functions for adding to each exclusion or targeting list, such as `excludeContract`, `targetSender`, or `targetArtifactSelector`. It also exposes read-only functions that allow external systems to retrieve the current state of these configuration lists, for example, `excludeContracts()` or `targetArtifacts()`. There are no access control mechanisms; any caller can modify these lists. No events are emitted, and there are no fees or complex mathematical operations. The contract's primary purpose is to store and retrieve these testing parameters.
