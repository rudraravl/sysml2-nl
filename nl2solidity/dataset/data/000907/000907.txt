This contract provides foundational upgradeability mechanisms for proxy contracts, allowing their underlying logic to be changed. It maintains three key state variables: the address of the current implementation contract, the address of the contract's administrator, and optionally, the address of an upgradeable beacon that points to an implementation. Callers can initiate an upgrade to a new implementation contract, optionally executing a setup function on the new implementation, or upgrade to a new beacon contract, also with an optional setup call. The contract also allows the administrator address to be changed. All upgrades and administrator changes emit corresponding events to signal these critical state transitions. A notable mechanic for UUPS proxies involves a rollback test during upgrades to ensure compatibility with older implementations. The contract enforces that new implementation and beacon addresses must point to valid contract addresses.
