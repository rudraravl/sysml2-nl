This contract provides a mechanism for managing the initialization lifecycle of other contracts, particularly those designed to be deployed behind a proxy. It maintains a version number representing its initialization state and a flag indicating if an initialization process is currently active. Callers can trigger an initial setup using an `initializer` function, which can only be executed once for version 1. Subsequent re-initializations for higher versions are possible via `reinitializer` functions, provided the requested version is greater than the current one and no initialization is ongoing. A `onlyInitializing` modifier restricts certain functions to be called exclusively during an active initialization phase. The contract also offers a way to permanently disable all future initializations by setting the version to its maximum value. Each successful initialization or re-initialization emits an `Initialized` event, indicating the new version.
