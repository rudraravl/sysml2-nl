This contract provides a robust initialization and re-initialization mechanism for upgradeable contracts, ensuring functions are called only once or in a specific version order. It maintains a state indicating whether the contract is currently initializing and tracks the highest version it has been initialized to. Callers can use the `initializer` modifier to mark a function for single-time execution upon initial deployment, or the `reinitializer` modifier to allow multiple initializations, each tied to a specific version number, preventing re-initialization to an older or same version. A special `onlyInitializing` modifier restricts functions to be called exclusively during an initialization process. An `Initialized` event is emitted whenever an initialization or re-initialization completes, including the version number. Additionally, a `_disableInitializers` function allows permanently locking the contract against any further initializations, which is useful for implementation contracts in a proxy pattern.
