This contract acts as an upgradeable beacon, managing the implementation address for a set of proxy contracts. It maintains two key pieces of state: the current implementation address that proxies should point to, and the address of the contract's owner. Upon deployment, an initial owner and implementation address are set. The owner has exclusive control over updating the implementation address via the `upgradeTo` function, which emits an `Upgraded` event, and can also transfer ownership to a new address or renounce it entirely, both actions emitting an `OwnershipTransferred` event. Callers can query the current implementation address and the current owner. The contract ensures that a new implementation address must correspond to a deployed contract with code, and a new owner cannot be the zero address.
