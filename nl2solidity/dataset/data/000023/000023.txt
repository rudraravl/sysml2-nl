This contract serves as a base for receiving cross-chain messages, acting as a recipient for an ERC-7786 compliant system. It maintains no explicit state itself, but rather provides a framework for processing incoming messages. The primary operation is `receiveMessage`, which allows a designated gateway to send messages to this contract. Before processing, the contract verifies if the calling `gateway` is authorized to send messages on behalf of the specified `sender` through an internal, customizable check. If unauthorized, the transaction reverts with an error indicating the unauthorized gateway and sender. If authorized, the message is then passed to an internal, customizable function for further processing. This design ensures that only trusted gateways can relay messages, and the contract relies on the gateway to prevent duplicate message delivery.
