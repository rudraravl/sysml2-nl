This contract implements an ERC-20 token with an extension allowing transfers to be authorized by signatures, eliminating the need for the token holder to send a transaction themselves. It maintains a record of used nonces for each account to prevent replay attacks. Callers can initiate a `transferWithAuthorization` by providing a signed message from the token holder, specifying the sender, recipient, amount, a validity window (either timestamp or block number based), and a unique nonce. Alternatively, a recipient can initiate a `receiveWithAuthorization` with a signed message from the sender. Token holders can also `cancelAuthorization` for a specific nonce by providing a signed message. The contract emits `AuthorizationUsed` and `AuthorizationCanceled` events when an authorization is consumed or invalidated. All authorization functions verify the signature and the validity window, and ensure the nonce has not been previously used.
