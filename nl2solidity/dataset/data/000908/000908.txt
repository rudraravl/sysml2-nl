This contract provides a mechanism to manage the initialization state of other contracts, particularly those designed to be used behind proxies where traditional constructors are not suitable. It maintains two internal state variables: one indicating the highest initialization version reached and another tracking if an initialization process is currently active. Callers can trigger initialization using either a generic `initializer` function, which can only be called once, or a versioned `reinitializer` function, allowing for multiple initialization steps as a contract evolves. The contract emits an `Initialized` event with the relevant version number upon successful completion of any initialization. Additionally, it offers a function to permanently disable all future initializations, which is useful for locking down implementation contracts. It also includes internal functions to query the current initialization version and whether an initialization is in progress.
