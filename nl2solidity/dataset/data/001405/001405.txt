This contract acts as an upgradeable proxy, serving as a fixed entry point for interactions with a separate, upgradeable implementation contract. It maintains a single piece of state: the address of the current implementation contract, stored in a specific storage slot to prevent conflicts. All calls made to this proxy are automatically delegated to the current implementation contract, effectively executing the logic defined there. Upon deployment, the contract is initialized with an initial implementation address and optional data to call a setup function on that implementation. The contract emits an `Upgraded` event whenever the underlying implementation contract is changed, allowing off-chain systems to track these updates. There are no direct functions for callers to interact with; all operations are performed via delegatecall to the implementation. The contract ensures that any new implementation address is a valid contract.
